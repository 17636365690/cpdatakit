# v0.10.1 repair verification

Prepared 2026-10-02 for the release candidate based on main
`f26a97584e6dc8eee415580847a7281ce76c7508`. This record describes local evidence; hosted CI and
publication are separate gates, visible on the release PR and tag workflow. It is not a claim
that a local build has already reached PyPI.

## Scope and preservation

The candidate repairs numeric ingestion/unit-conversion precision, HDF5 implicit dependencies,
multipart budgets, multi-workspace sessions, conversion provenance, bounded HDF5 reads/report
scans, Windows NetCDF3 Unicode input paths, and package-documentation links. It corrects adjacent
writer-capability and roadmap statements without adding CSV export, date schemas, new adapters,
training features or cloud services. Runtime dependencies and Python >=3.12 remain unchanged.

Development used an isolated worktree. Existing sibling checkouts were preserved. All new test
inputs are synthetic; no private experimental data, raw third-party download, virtual environment,
browser workspace, local trace or machine-specific report is part of the release changes.

## What the new boundary tests establish

- Nullable signed/unsigned integer input and identity mappings preserve exact values. Unsafe mixed
  promotion, integer result rounding, overflow and nonzero underflow are rejected with locations.
- External HDF5 links, raw external storage, VDS and SoftLink are rejected before payload access;
  safe hard-link aliases/cycles work. No external target content is needed to diagnose rejection.
- Oversized multipart files are stopped before the complete body is spooled, including missing or
  misleading Content-Length, a single large ASGI frame, streamed data and prefixed Content-Type.
  Malformed bodies, disconnects and cancelled tasks close their owned spools.
- CSV receipts survive repeated HDF5/Parquet conversions, with original source/parse/exclusion
  information retained. Each step records only its newly applied mapping, while prior receipts
  remain available. Inconsistent digests/links are rejected; unknown old history is not fabricated.
- Rejected HDF5 record/materialization limits incur zero dataset-payload reads. Selected reads and
  coordinate semantics remain exact; cancellation prevents output publication. Global validation
  is not replaced with partial per-chunk validation.
- Identical native NetCDF3 bytes load under ASCII and Unicode Windows paths, including date
  decoding and selected rows. Temporary snapshots and handles are removed on success/failure/
  cancellation; surviving source hints refer to the original file.

## Bounded performance evidence

Four-column synthetic HDF5 files, five repeated measurements per size and phase, same Windows
environment. Timing excludes imports. Peak working set was sampled every 5 ms, so it can miss a
short-lived peak. OS caches were not cleared and other development work could run concurrently.
The structural read-count assertions are stronger evidence than these absolute timings.

| Report input | Before median and range (s) | After median and range (s) | Maximum sampled working set before/after (MiB) |
|---|---|---|---|
| 10,000 rows × 4 | 0.2564 (0.2298–0.2755) | 0.0935 (0.0918–0.1065) | 117.59 / 115.03 |
| 100,000 rows × 4 | 2.4038 (2.2906–2.4409) | 0.8571 (0.8440–0.8614) | 151.48 / 130.91 |

Native inspect-with-schema and report payload passes decreased from two/three to one. These
results do not establish GB-scale throughput, long-running memory stability or a universal speedup.

## Limits and publication gates

ReadLimits estimate materialized array storage, not process RSS or a native-library sandbox.
Simple variable-length HDF5 strings use a conservative file-size/count bound; other variable-length
types can be rejected under explicit bounds. The native NetCDF4 Windows Unicode path may require
temporary disk space equal to the source size. Date-coordinate schema support is still separate.
Provenance hashes establish internal consistency, not authorship or physical validity.

The 40 full-suite warnings include dependency deprecations, date decoding and experimental Zarr
representations. The lower combination also emits a netCDF4/NumPy binary-size RuntimeWarning;
passing the selected cases does not prove every native ABI combination safe.

Before publishing, the exact final source must pass hosted required checks, reproducible wheel/
sdist builds, metadata/link checks and the existing protected OIDC deployment. The release uses
the existing publishing workflow and environment without weakening protections. PyPI installation
and GitHub/PyPI artifact hashes must be verified after the tag workflow succeeds.
