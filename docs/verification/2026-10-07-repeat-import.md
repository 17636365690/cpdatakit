## 唯一的共性改进

在现有 CSV 工作台增加“保存已确认导入设置”、载入设置及新文件差异预览。
继续使用既有 `preview_csv`、`prepare_csv`、列声明、schema 与转换流程。
设置只含 `options`、`columns` 和 `source_columns`（不含样本值的原始列记录）。
旧身份、来源说明、实验条件及哈希不复用；新文件必须重新说明、确认和计算哈希。

同结构文件填入已确认的列名、单位、类型、用途及排除项。列数、顺序、名称、检测类型、
可见单位或解析选项变化时显示旧值/新值，列声明不自动套用。旧设置缺原始列记录时
只载入解析选项，要求重新确认。导入清单记录本次设置比较；导出设置先核对同一次
限长读取的源文件和清单字节哈希。原有直接 API 调用继续由调用者负责提供正确的位置声明。

不增加批处理引擎、单位推断、YAML 适配器、样品自动关联或光谱分析算法。
无表头、重复且无法区分的列或未写入 CSV 的单位改变，不能仅靠结构判定，仍须核对来源。

## 两类真实任务

| 案例 | 实际验证 | 第二份重复填写减少 |
| --- | --- | --- |
| echemdb purple / brown | 3,501 / 5,001 行；原始 CSV、HDF5、unitpackage Entry 重开逐值一致，最大差 0；原字节、s/V/A 与列序保持；KI/KBr 各自 YAML、SCE 标度与 Pt-Pseudo 电极分别保留 | 6 个单位单元格、3 个用途；列名原本已有默认值，不虚计收益 |
| PyIRoGlass a / b 光谱 | 两条各 3,942 行，配 9 行成分/厚度表；数字、单位、顺序、Sample 精确关联及独立来源哈希；缺失/重复 ID 均由对应校验拒绝 | 2 个列名、4 个单位单元格、2 个用途，含 `coordinate` 原值 |

来源、许可与固定版本见 [案例说明](../../examples/repeated-import/README.md)。
echemdb 原生 unitpackage API 实跑；PyIRoGlass 因 NumPy 版本冲突与 Windows mc3 编译限制，
执行固定源码中未经改写的 `SampleDataLoader` 类及原始必要 imports。其来源 SHA、
AST 一致性、全谱和默认 1000–5500 cm⁻¹ 区段结果均保存；这不是完整 PyIRoGlass 安装成功。
未运行 MCMC。光谱和表的使用文件与 Zenodo 归档对应成员逐字节相同，GPL 源码仅在外部案例中。

CSV/HDF5 数值比较为精确 float64；独立原生光谱解析预先约定 rtol=1e-14、atol=1e-12，
本次原始光谱最大差也为 0。echemdb 原生路径预先约定 rtol=1e-12、atol=1e-15，
本轮同样达到精确相等。不调整单位、排序、筛除异常或降低数值标准来取得通过。

## 保留的失败与结论边界

保留旧 API 盲按位置复用造成字段错绑的隔离复现、缺失/重复 ID、旧哈希拒绝、
TDD 初始失败、超大设置的 413、完整 PyIRoGlass 安装失败及所有验收修正记录。
浏览器首次回读 41/43 的两项文本失败只因 HTML 表单将 LF 序列化为 CRLF；
归一化换行表示后逐字相等，独立 YAML 语义、CSV 原字节及数值始终保持严格对照。

减少的是 CPDataKit 工作台内部重复录入。原生项目已有批量/元数据能力，案例仍需
各文件科学信息、来源审阅以及领域衔接代码；没有证明整体更省时或比原生流程更方便。
未测量人工时间，也不把代理运行耗时当作收益。工程交接通过不等于实验、标定、拟合、
物理有效性或跨数据泛化成立。

维护支线仅只读核对：PR #51/#52 保持开放，#52 落后主分支，应独立更新后重验；
Issue #4 的流式内存基准、Issue #6 的具体新适配器需求仍有未完成范围。
