# v0.12.0 release verification

The release simplifies the local workbench presentation and adds one bounded preview field. CSV
parsing, declarations, normalization, validation, conversion, reports, settings reuse, output
recovery and the HTTP routes keep their existing contracts. File-specific source descriptions and
hashes remain per import.

## Interface changes checked

- The project page is one column without the step sidebar, outer cards, duplicated context bar,
  status badges or explanatory banners. In the same state (synthetic `instrument.csv` previewed,
  nothing declared, 1024 px), visible controls fell from 61 to 25, computed font sizes from nine to
  three (12, 13 and 20 px), weights from four to two, families from two to one, and page height
  from 3,447 to 1,315 px.
- CSV declarations render as text summaries. Opening an editor expands only that row and locks
  other row actions; Escape or Cancel keeps prior values and focus returns to the row action.
- Import stays disabled while a row is open, a required declaration or source description is
  missing, no column is kept, or a server error located to a column is unresolved. Field, kept-column
  and source-description changes clear the previous confirmation.
- `preview_csv` returns `sample_rows` with one-based physical line numbers. The raw preview uses
  only these aligned records; without them the raw preview is unavailable. Exported reusable
  settings do not contain them.

## Local evidence

Frontend behaviour tests run the shipped browser modules in Node: 48 scenarios, including 11 new
scenarios written before the implementation and observed failing against v0.11.0. They cover
summary-first rendering, one-row editing, reconfirmation, zero kept columns, missing source text,
duplicates, text/numeric switching, located server errors, stale preview responses, the raw preview
contract, collapsible source text, job visibility and quiet paging.

A Chromium run against a local server checked 21 user-flow assertions: keyboard open/cancel/apply
and focus return, server unit rejection without registration, import with source/manifest download,
validation, conversion, reports, exact HDF5 readback, explicit overwrite confirmation, an outside-
project output failure, snapshot continuation with the original rules, same-structure settings reuse
with an independent source description, and drift rejection. Layouts at 1440, 1024, 768 and 390 px,
plus 1152, 960 and 720 px as 125/150/200 % zoom equivalents at 1440 px, had no horizontal overflow;
pending items and errors stayed visible.

The same run imported one public IN718 tensile export (Mendeley 10.17632/nx55jj48rx.2,
CC-BY-4.0; 1,865 records; SHA-256 `e4a33b2f89b218fd94a36bf6e5b48c9b34139fd0e046d07e2304383bff5619b4`),
validated, converted and reported it, and read the HDF5 values back with a maximum absolute
difference of 8.9e-16 against the source after the declared N to kN conversion. This is an
engineering workflow check only.

These browser checks ran on the development checkout before the version metadata changed; the
interface code is identical. For v0.12.0 itself, the full suite recorded 1,869 passed, 1 skipped
and 40 warnings on Windows with Python 3.12.10, with 90.52 % total coverage. Ruff check and format
check passed. Two
non-isolated builds with the pinned hatchling 1.32.0 matched byte-for-byte; `check_release.py`,
`twine check` and a clean-wheel installation passed, and both installed-wheel browser smoke scripts
passed against that wheel. HDF5 read diagnostics returned exact record counts for 100,000 and
1,000,000 records; peak RSS is not reported on Windows.

## Limits

Browser checks used Chromium only. Zoom was emulated through viewport width, and screen readers were
not tested; below 600 px the field table is presented as stacked rows. Unit compatibility is still
checked by the server at import, and column location of server errors depends on its existing
message format. The interrupted-output recovery page keeps its earlier presentation. The original
IN718 archive was not available locally, so the smoke script's `--source-zip` mode was not run.

No physical validity, calibration, measured time savings or experimental generalization is
established. Remote CI results belong to their exact commit; publication is accepted only when the
tag, GitHub Release, PyPI artifact hashes and a fresh installation from the public index agree.
