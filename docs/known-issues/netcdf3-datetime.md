# NetCDF3 与日期坐标：独立兼容性问题

状态：2026-09-29 的真实文件试用记录存在失败；2026-09-30 至 2026-10-01 的 CSV 完善没有修改
这两个格式路径，也没有把历史重封装结果计为原生支持。它们不阻塞本轮 CSV → HDF5 工作流。

## 历史证据

使用 xarray 示例 `air_temperature.nc` 的原始 NetCDF3 容器时，默认读取、检查、规则草稿和切片失败。
当时默认 h5netcdf 后端没有读入原容器。外部将容器重封装为 NetCDF4 后，数值、维度、dtype
和属性逐项比较一致，检查与切片能运行；这条结果属于外部兼容处理。

NetCDF4 兼容副本的 `time` 坐标为 `datetime64[ns]`。把该坐标写入规则后，验证/转换路径返回
不支持该 dtype 的错误。容器可读和规则支持日期类型是两个问题。

完整记录保存在此前的 `公开多维气温/trial_summary.json` 与来源清单中；本轮没有重新运行该案例。
不能把本轮 CSV 验收或数值型 NetCDF 自动测试通过写成日期坐标验证通过。

## 后续验收范围

规则日期类型、坐标精度和编码单位，再分别测试读取、验证、转换、报告与切片。
