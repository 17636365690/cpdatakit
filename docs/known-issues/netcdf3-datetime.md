# NetCDF3 与日期坐标：独立兼容性问题

状态：v0.10.1 修复 Windows 中文路径下的原生 NetCDF3 读取；日期坐标的通用 schema 支持
仍不在本次修复范围。容器读取、日期解码与 schema 验证是不同的合同。

## 当前行为

应用按 CDF 文件头选择 netCDF4 后端。Windows 的该原生后端处理非 ASCII 路径时，读入器先
按块创建临时 ASCII 副本，再在同一上下文中读取；不重封装、不修改原件，成功、拒绝或取消
后清理副本。显式文件字节限额在复制前及复制中检查，复制可取消；未指定限额的读取保留既有
非限额合同，并额外需要一份文件大小的临时磁盘空间。

默认使用系统临时目录；若其路径也非 ASCII，会尝试系统已有的短路径。短路径不可用时明确
要求选择 ASCII 的 TEMP 目录，不创建全局目录或替用户修改环境配置。h5netcdf 的正常 NetCDF4
路径和 POSIX 路径不需要这个副本。

本次相同字节的两行合成 NetCDF3 在中文和英文路径下保持温度、单位、属性及日期坐标一致，
选择读取仍保留原日期精度。`datetime64` 可作为坐标读出，但当前规则类型仍不支持完整日期
语义；不得把它写成日期验证或日期转换功能。需要预处理时应明确记录时区、calendar及编码单位。

## 历史证据

使用 xarray 示例 `air_temperature.nc` 的原始 NetCDF3 容器时，默认读取、检查、规则草稿和切片失败。
当时默认 h5netcdf 后端没有读入原容器。外部将容器重封装为 NetCDF4 后，数值、维度、dtype
和属性逐项比较一致，检查与切片能运行；这条结果属于外部兼容处理。

NetCDF4 兼容副本的 `time` 坐标为 `datetime64[ns]`。把该坐标写入规则后，验证/转换路径返回
不支持该 dtype 的错误。容器可读和规则支持日期类型是两个问题。

完整记录保存在当时的试用日志与来源清单中。本次使用可独立生成的原生 NetCDF3 夹具验证路径
修复，不把早期外部重封装或历史真实案例算作本轮重新验收。

## 后续验收范围

单独建立保留原始 NetCDF3 与日期坐标的小型可公开夹具，确认原生读取的后端选择、错误提示、
规则日期类型、坐标精度和编码单位，再分别测试读取、验证、转换、报告与切片。
继续保留原文件和兼容副本的版本边界，按名称和值独立核对坐标；不为格式兼容改变科学含义。
