# CPDataKit v0.6 Preflight Design

**Date:** 2026-09-02
**Status:** Proposed preflight after maintainer approval of Python 3.12 as the v0.6 minimum.

## Goal

Prepare CPDataKit v0.6 so implementation starts from measured dependency and compatibility facts.
The preflight does not ship the Web UI or N-dimensional format support. It locks the contracts,
fixtures, dependency matrix, service boundaries, and format specifications those features will use.

## Accepted decisions

- v0.6 requires Python 3.12 or later.
- v0.5.x remains available for Python 3.10 and 3.11.
- `pip install cpdatakit` will include the local Web UI and open-source v0.6 formats.
- UI, CLI, and Python API share application services.
- `Dataset`, schema 1.0, HDF5 1.0, existing profiles, CLI commands, and imports remain compatible.
- N-dimensional data uses a new xarray-backed `ScientificDataset`; `Dataset` is not replaced.
- Current xarray and Zarr 3 behavior is preferred over maintaining different format semantics for
  different Python versions.
- FastAPI dependencies are listed explicitly. The default install does not include FastAPI Cloud
  tooling or require Node.js at runtime.

## Dependency findings

The v0.5 floor is NumPy 1.24, pandas 2.0, and Python 3.10. Current upstream requirements have moved:

- Current xarray requires Python 3.11, NumPy 1.26, and pandas 2.2 or later.
- Current Zarr requires Python 3.12 and NumPy 2.0 or later.
- Current PyArrow publishes wheels for Python 3.10 through 3.14.
- Current FastAPI supports Python 3.10 or later.

These constraints make Python 3.12 the first common baseline that can use the current stack without
conditional format behavior. The preflight records exact tested lower bounds rather than copying
latest versions into production metadata without evidence.

## Preflight workstreams

### 1. v0.5 compatibility charter

Create machine-readable snapshots for:

- Package-root exports and callable signatures.
- CLI commands, options, help text, and exit-code behavior.
- Built-in schema canonical JSON and pinned hashes.
- HDF5 1.0 root attributes, groups, round trips, and legacy fixtures.
- CP curve, point, field2d, DAMASK, Surfalex, and thermal-cycle workflows.
- Report, inspection, schema-diff, and comparison payload shapes.

The snapshots protect behavior, not source layout or incidental wording. Additive v0.6 APIs may
extend snapshots. Removing or changing a v0.5 entry requires an explicit compatibility decision.

### 2. Dependency matrix probe

Build isolated environments for Python 3.12 and 3.13 on Windows, Linux, and macOS where available.
Test two dependency sets:

- Lower-bound candidate set for repeatable support.
- Latest compatible set to detect upstream drift.

The probe installs and imports NumPy, pandas, xarray, Zarr, PyArrow, the selected NetCDF engines,
FastAPI, Uvicorn, Jinja, multipart parsing, and CPDataKit. It records resolved versions, wheel
availability, install size, cold import time, licenses, and a minimal read/write operation for every
format. No candidate becomes a runtime dependency until both matrices pass.

FastAPI is installed as focused packages rather than `fastapi[standard]`. UI tests add HTTPX as a
development dependency. The NetCDF probe compares `h5netcdf` against `netCDF4` for format coverage,
wheel availability, and installed size. The accepted engine set must read the checked-in NetCDF
fixture on all three operating systems.

### 3. Data model contract

Specify `ScientificDataset` independently of any reader:

```python
@dataclass(slots=True)
class ScientificDataset:
    data: xarray.Dataset
    metadata: dict[str, Any] = field(default_factory=dict)
    source: Path | None = None

    def copy(self) -> ScientificDataset: ...
```

The contract defines:

- Ordered dimensions and coordinate variables.
- Data-variable dimensions, dtype, unit, role, and component labels.
- JSON-compatible metadata and provenance boundaries.
- Deep-copy behavior.
- Exact lossless conversion conditions between `Dataset` and `ScientificDataset`.
- Errors for ragged values, ambiguous record axes, unsupported object arrays, and lossy flattening.

The model does not contain format-specific handles, lazy backend objects that cannot be copied, or
implicit unit inference. Lazy arrays may be supported through xarray only after lifecycle ownership
is explicit.

### 4. Schema 2.0 contract

Write normative JSON fixtures for dimensions, coordinates, variables, attributes, chunks, and
composition. Include:

- One standalone schema.
- One `extends` example.
- One two-fragment `includes` example.
- Cycle, collision, incompatible override, and missing-source failures.
- Fully resolved canonical JSON, source manifest, and exact SHA-256 values.

Schema 2.0 resolution is local and deterministic. It never fetches HTTP sources by default. Schema
1.0 parsing and canonical hashes use the existing code path and remain byte-identical.

### 5. HDF5 2.0 protocol

Freeze a written layout before implementing the writer. The protocol specifies:

- Required root attributes and version dispatch.
- Dimension, coordinate, variable, and metadata groups.
- Ordered dimension references for every variable.
- Dtype and string encoding.
- Unit, role, chunk, compression, and fill-value metadata.
- Canonical schema snapshot and digest.
- Provenance, validation summary, and migration manifest.
- Atomic writes, bounded reads, and corruption failures.

Create one small hand-authored fixture and one malformed fixture set. The v1 reader remains a
separate implementation. HDF5 2.0 code cannot weaken v1 metadata checks.

### 6. Format capability contracts

Define reader and writer protocols before adding implementations:

```python
class DatasetReader(Protocol):
    info: ReaderInfo

    def detect(self, path: Path) -> DetectionResult: ...
    def inspect(self, path: Path, *, limits: ReadLimits) -> InspectionResult: ...
    def load(self, path: Path, *, selection: Selection | None = None) -> DataValue: ...


class DatasetWriter(Protocol):
    info: WriterInfo

    def check(self, data: DataValue) -> CapabilityResult: ...
    def write(self, data: DataValue, output: Path, *, force: bool = False) -> Path: ...
```

`DataValue` is a closed union of `Dataset` and `ScientificDataset` in v0.6. Detection is bounded and
may return multiple candidates. Writers explain unsupported variables before creating output.

The preflight produces capability tables for HDF5 1.0, HDF5 2.0, NetCDF, Zarr 3, and Parquet.
Parquet remains tabular and never receives arbitrary N-dimensional arrays through silent flattening.

### 7. Application service boundary

Map existing CLI flows into use cases without changing their behavior:

- Import and inspect.
- Resolve schema and mapping.
- Validate and summarize.
- Convert and write.
- Build reports and comparisons.
- Plot declared fields.

Each use case has typed input and output values and no dependency on argparse, HTTP requests,
templates, or browser sessions. The existing CLI calls these services through a compatibility
adapter. The Web layer is deferred until the service tests pass.

### 8. UI and catalog threat/operation model

Document the local UI boundary before selecting routes and templates:

- Loopback binding and host validation.
- Random session token and CSRF behavior.
- Workspace creation and path containment.
- Upload size and bounded preview limits.
- Archive traversal rejection.
- Atomic output and overwrite confirmation.
- Job cancellation and process ownership.
- SQLite location, migrations, backups, and file-reference behavior.
- No outbound requests, CDN assets, telemetry, or cloud account.

This document feeds route and catalog tests. The preflight creates no listening server.

### 9. CI preparation

Before v0.6 feature code:

- Move the project matrix to Python 3.12 and 3.13.
- Add macOS clean-wheel and dependency-probe jobs.
- Keep a separate v0.5 maintenance workflow or documented branch policy for Python 3.10/3.11.
- Run branch push CI only on `main`; PRs run through `pull_request`, avoiding duplicate feature runs.
- Update GitHub Actions that still trigger Node.js 20 deprecation warnings.
- Cache pip downloads without caching generated scientific fixtures or output artifacts.

The Python-floor change, dependency additions, and CI changes land together so the repository never
advertises an untested combination.

## Candidate N-dimensional reference case

Use a deterministic thermal-field dataset with dimensions `time`, `y`, and `x`:

```text
temperature(time=4, y=3, x=4) [K]
time(time=4) [s]
y(y=3) [mm]
x(x=4) [mm]
stage(time=4) [string]
```

The case is small enough for source control and contains no CP semantics. It proves coordinates,
dimension order, scalar metadata, a categorical coordinate, chunk choices, schema 2.0, and the
HDF5/NetCDF/Zarr paths. Values are generated by a fixed formula documented beside the fixture.

Use the existing thermal-cycle table as the lossless conversion case. A second variable with
dimensions that cannot map to one record axis proves that reverse conversion fails clearly.

## Measurements to record

- Fresh installation size by dependency and total.
- Cold import time for `cpdatakit`, xarray, Zarr, PyArrow, and the Web entry point.
- Read/write time and output size for the small reference case.
- Peak memory and bounded-preview reads for a generated larger case.
- Wheel availability on the supported OS/Python matrix.
- Exact resolved lower-bound and latest-compatible dependency sets.

These are diagnostics, not performance promises. The committed benchmark output records machine and
dependency versions.

## Exit criteria

The preflight is complete when:

- Python 3.12 and 3.13 dependency probes pass on Windows and Linux; macOS wheel smoke passes.
- Exact dependency floors and license changes are reviewed and documented.
- v0.5 public behavior snapshots pass against the v0.6 branch.
- `ScientificDataset`, schema 2.0, HDF5 2.0, reader/writer, service, and UI security contracts have
  approved normative fixtures or interface definitions.
- The N-dimensional reference case and malformed fixtures are checked in with deterministic hashes.
- No Web route, catalog database, or format writer is implemented before its owning contract test
  can be written.

## Work deferred until preflight approval

- Runtime dependency changes in `pyproject.toml`.
- `ScientificDataset` implementation.
- Schema 2.0 resolver and HDF5 2.0 reader/writer.
- NetCDF, Zarr, and Parquet production readers/writers.
- Application service refactor.
- FastAPI routes, templates, browser assets, SQLite catalog, and job manager.
