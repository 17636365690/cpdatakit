# CPDataKit Post-v0.3.0 Stabilization and v0.4.0 Planning Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the locally verified CPDataKit v0.3.0 snapshot into an auditable repository baseline, close the three confirmed boundary gaps, and prepare independently reviewable v0.4.0 work without changing the solver-neutral contract or silently expanding adapter scope.

**Architecture:** First establish a clean branch from the public v0.3.0 tag and reconcile the current workspace against it; the present parent Git repository has no commits or remote and contains malformed Codex-only refs, so it is not reliable release history. Then harden the HDF5/validation/CLI boundaries with focused red-green tests. After that, split v0.4.0 into schema migration and comparison/report-bundle subprojects, while handling large-file performance and the first optional adapter as evidence-gated workstreams.

**Tech Stack:** Python 3.10+, pandas, NumPy, h5py, Pint, pytest, Hypothesis, Ruff, Hatchling, GitHub Actions, GitHub Releases, and PyPI Trusted Publishing.

**Spec:** `docs/roadmap.md`, `docs/data-format.md`, the seven completed v0.2/v0.3 design records under `docs/superpowers/specs/`, and the audit evidence recorded in this plan.

## Global Constraints

- Keep CPDataKit HDF5 `format_version` and the schema contract at `1.0` until a separately approved compatibility design exists.
- Preserve `load_dataset(path)` as the full-read entry point and keep `load_hdf5()`/`iter_hdf5_chunks()` record-axis semantics unchanged.
- Keep schema, unit, tensor-order, orientation, stress/strain-measure, and identifier decisions explicit; add no scientific inference.
- Keep HDF5 writes atomic, protect existing outputs unless `force=True`, and never fetch `schema_uri`.
- Keep reports aggregate-only, path-portable, credential-redacted, static, and offline.
- Keep DAMASK DADF5 read-only and keep solver runtimes, Abaqus ODB files, and restricted source data out of core dependencies and fixtures.
- Treat warnings as non-invalid unless the CLI contract is explicitly changed and documented; `ValidationResult.valid` currently means zero errors.
- Do not republish or retag v0.3.0; release and GitHub mutations require a reviewed maintainer workflow.
- Keep generated `.venv`, `build`, `dist`, coverage, cache, HDF5, and image outputs out of source commits unless a specific artifact is intentionally approved.

## Verified baseline and known discrepancies

- Local source reports version `0.3.0`; 196 tests pass with 86.62% coverage; Ruff check and format check pass.
- Two local source builds are byte-for-byte reproducible; `check_release.py v0.3.0` and Twine checks pass; a dependency-complete temporary wheel smoke passes.
- The 100,000- and 1,000,000-record HDF5 benchmarks return exact counts for full, selected-field, and chunked reads. RSS is `null` on this Windows run, so it is diagnostic evidence only.
- The local `dist/` directory still contains old v0.2.0 artifacts; the verified v0.3.0 artifacts were created outside the repository and must not be confused with checked-in release evidence.
- The parent Git repository has no commits, no configured remote, a `master` HEAD, and malformed `refs/codex/turn-diffs/...` entries. Do not repair or delete that metadata until the source has been compared with a clean clone.
- Public GitHub and PyPI already expose v0.3.0; GitHub issues #4 (“Benchmark and optimize large CPDataKit HDF5 reads”) and #6 (“Contribute the first optional CPDataKit adapter”) remain open.
- Four behavior gaps are not currently locked by tests: non-canonical but hash-matching `schema_json` is accepted, ragged shaped values can raise a raw NumPy `ValueError` during validation, an empty in-memory dataset can be written but cannot be read back, and warning-only inspection currently returns status `0` under the documented non-error semantics.

- [ ] **Step 1: Lock canonical schema snapshot bytes before implementation**

  Add an I/O regression that writes a valid file, replaces `schema_json` with pretty-printed JSON
  for the same schema while retaining the canonical digest, and expects `DataReadError` naming
  `schema_json`. Add the positive round-trip assertion that the writer’s stored text equals
  `schema_to_canonical_json(schema)` exactly. The reader may continue accepting legacy files that
  contain no snapshot at all.

- [ ] **Step 2: Make ragged shaped validation return a structured finding**

  Add a validation test with a ragged nested value such as `[[1.0, 2.0], [3.0]]`. It must return a
  `ValidationResult` containing `invalid_shape` and must not leak NumPy’s inhomogeneous-shape
  `ValueError`. Update `_matches_shape()` and any dtype helper it calls to treat NumPy conversion
  `TypeError`/`ValueError` as a failed shape or dtype check, then run the focused validation tests.

- [ ] **Step 3: Make empty HDF5 writes fail closed before temporary-file creation**

  Add an I/O test that passes an empty DataFrame with declared columns to `write_hdf5()` and
  monkeypatches `tempfile.mkstemp`; the call must raise a documented `DataValidationError` (or a
  more specific existing `CPDataKitError` selected during implementation), create no target, and
  create no temporary file. Keep the reader’s nonzero-record contract unchanged. Do not make
  `allow_invalid=True` produce an artifact that the current reader cannot open.

- [ ] **Step 4: Update the format contract and changelog**

  Document that shaped-value validation handles ragged arrays as findings and that CPDataKit HDF5
  output is non-empty and canonical when written. Add an Unreleased entry for canonical snapshot
  enforcement, ragged-value handling, and empty-output protection without changing the `0.3.0`
  heading or release metadata.

- [ ] **Step 5: Run the focused red-green cycle and the full gate**

  Run `pytest tests/test_io.py tests/test_validation.py -q`, then the full 196-test-equivalent suite
  with the 85% coverage gate, Ruff check, Ruff format check, and a temporary reproducible build.
  Verify the temporary-file assertions explicitly before proceeding to release reconciliation.
