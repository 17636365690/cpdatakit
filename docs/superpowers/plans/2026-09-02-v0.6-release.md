# CPDataKit v0.6 Release Implementation Plan

> **For agentic workers:** Execute this plan inline in the current nested repository with strict
> red-green-refactor TDD. Existing uncommitted preflight files are user assets and must remain in
> place. Release integration is performed only after every verification gate below passes.

**Goal:** Turn the measured v0.6 preflight into a releasable Python 3.12+ local-first scientific
workbench while preserving every v0.5 public, CLI, schema 1.0, and HDF5 1.0 contract.

**Architecture:** Additive packages sit behind the existing `Dataset`, CLI, and public import surface.
`ScientificDataset`, schema 2.0, and HDF5 2.0 are separate representations; readers and writers use
the existing format capability boundary; UI, CLI, and Python callers use typed application services.
The local UI owns HTTP/session concerns, while catalog and job records reference workspace-relative
files and never own source bytes implicitly.

**Tech Stack:** Python 3.12/3.13, Hatchling, NumPy, pandas, h5py, xarray, Zarr 3, PyArrow, h5netcdf,
netCDF4, FastAPI, Uvicorn, Jinja2, python-multipart, HTTPX, SQLite, pytest, pytest-cov, Ruff, HDF5,
JSON, and GitHub Actions Trusted Publishing.

**Spec:** `docs/superpowers/specs/2026-09-02-local-first-scientific-platform-design.md`

## Global Constraints

- Keep the package name and `cpdatakit` import path.
- Keep the current tabular `Dataset`, `curve`, `point`, `field2d`, thermal-cycle profile, CLI
  commands, DAMASK adapter, and CPDataKit HDF5 1.0 reader.
- Existing HDF5 1.0 files remain readable. Writers use 1.0 for lossless tabular data unless a caller
  selects a feature that requires HDF5 2.0.
- No operation silently flattens N-dimensional arrays, changes units, rewrites tensor order,
  converts physical measures, or applies inferred semantics.
- v0.6 requires Python 3.12 or later. CPDataKit 0.5.x remains the supported line for Python 3.10
  and 3.11 users.
- `pip install cpdatakit` includes the local UI and open-source format support needed by v0.6.
- Windows, macOS, and Linux are supported for the core, UI, and open formats.
- Runtime dependencies are promoted only after the lower/latest dependency matrix passes on the
  supported hosted platforms.
- Local UI requests carry a random session token and CSRF protection; host checks reject non-local
  origins by default.
- Uploaded files enter a per-project workspace; file names are normalized and archive traversal is
  rejected.
- Solver processes never use `shell=True`; this release ships no proprietary solver runtime.
- Do not remove or mutate existing v0.5 snapshot fixtures; all new fixtures are deterministic.
- No source, commit, tag, push, release, or publish action is considered complete without fresh
  verification evidence.
