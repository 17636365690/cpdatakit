# CPDataKit v0.6 Preflight Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with strict red-green-refactor TDD. Steps
> use checkbox (`- [ ]`) syntax. The maintainer requested inline execution, so no subagents are used.

**Goal:** Produce measured dependency, compatibility, protocol, fixture, and security artifacts that
make v0.6 implementation safe to start without shipping unfinished Web or N-dimensional features.

**Architecture:** Preserve v0.5 runtime behavior while adding preflight-only contracts and probes.
Executable additions are limited to compatibility tests, dependency/fixture diagnostics, and
Reader/Writer interface values. ScientificDataset, schema/HDF5 2.0 engines, application services,
format implementations, Web routes, SQLite, and jobs remain outside this plan.

**Tech Stack:** Python 3.12+, Hatchling, pytest, Ruff, h5py, JSON, GitHub Actions, optional isolated
probe environments containing xarray, Zarr, PyArrow, NetCDF engines, FastAPI, and Uvicorn.

**Spec:** `docs/superpowers/specs/2026-09-02-v0.6-preflight-design.md`

## Global Constraints

- v0.6 requires Python 3.12 or later; v0.5.x remains the Python 3.10/3.11 line.
- Preserve every v0.5 package-root export, CLI command, schema 1.0 hash, HDF5 1.0 fixture, and
  validated workflow.
- Do not implement ScientificDataset, schema/HDF5 2.0 runtime engines, production NetCDF/Zarr/
  Parquet readers, Web routes, SQLite catalog, or job manager in preflight.
- Do not add runtime dependencies to `pyproject.toml` until the dependency probe passes.
- All checked-in fixtures are deterministic, small, license-safe, and generated without network
  access.
- Keep the unpublished v0.6 program/preflight specs as user assets.
- Do not commit, push, tag, or publish during this preflight unless separately requested.
- Replace commit steps with scoped `git diff --check` and status checkpoints.
